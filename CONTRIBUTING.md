# Contributing to AERO-X Protocol

Thank you for your interest in contributing.

## Before opening an issue

- Search existing issues and discussions for duplicates.
- Describe the problem, expected behavior, and reproducible steps.
- Do not include credentials, personal data, API keys, or exploitable vulnerability details.

## Pull request checklist

- [ ] Keep the change focused and explain its motivation.
- [ ] Update documentation when behavior or setup changes.
- [ ] Add or update tests where practical.
- [ ] Run the relevant checks locally: go test ./... and go vet ./....
- [ ] Do not claim unimplemented functionality or unverified performance/security properties.

## Scope

Contributions should improve the documented prototype. Major architectural changes should start with an issue or design discussion so assumptions and trade-offs can be reviewed first.

## Security reports

Do not disclose exploitable vulnerabilities in public issues. Use GitHub's private vulnerability reporting if enabled, or contact the maintainer privately.
